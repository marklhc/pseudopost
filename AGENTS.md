# Working in pseudopost

- This is one R package. `R/adjust.R` is the adjustment entry point; `R/sandwich.R` computes the closed Godambe (`pl_godambe`) and open-faced (`pl_ofs` / `ofs_square_root`) covariances; `R/draws.R` maps target covariance to adjusted draws; `R/requirements.R` validates cmdstanr fits (and, via `check_model_data_arg()`, models) against the pseudo-likelihood requirements; `R/magnitude.R` does the scalar magnitude rescale/refit. The Stan fixtures in `inst/test-models/` back the tests (including `nomag.stan`, a fixture that deliberately lacks `magnitude_adj` for the negative path); the detailed model requirements are in `vignettes/pseudo-likelihood-requirements.Rmd`.
- `ofs_square_root()` in `R/sandwich.R` must keep the ordering `Omega = Q^-1/2 S^(1/2) Q^(1/2)` so that `Omega %*% Omega = Q^-1 P` and the adjusted-draw covariance equals the Godambe target `Q^-1 P Q^-1` exactly under the one-bread assumption `C_emp = Q^-1`. The similar ordering `Q^(1/2) S^(1/2) Q^-1/2` squares to `P Q^-1` and does NOT reproduce the target (a past bug); the pure-R test in `test-unit-matrices.R` pins this on a non-commuting example.
- Run tests from the package root with `devtools::test()`; focus on a file with `devtools::test(filter = "combos")` (matches `test-combos.R`). For fast pure-R iteration use `PP_SKIP_STAN=1 Rscript -e 'devtools::test()'`. Full Stan-backed tests need cmdstanr, Rcpp, a working CmdStan installation, and (for the pairwise fixture) lavaan; they compile and sample, so are substantially slower.
- `tests/testthat/helper-fit.R` lazily compiles each Stan fixture once per R session with `force_recompile = TRUE` and caches the live `CmdStanModel`. Do not reuse a precompiled executable/model from another session for tests using `hessian`, `constrain_variables`, or `unconstrain_draws`: cmdstanr model methods fail on that path. Compilation writes executables into `inst/test-models/` next to the `.stan` sources; these are git-ignored and `.Rbuildignore`d -- never commit them.
- `tests/testthat/_reference/expectations.csv` is a regression baseline from the external pairwise-cfa implementation. `tools/capture_reference.R` regenerates it using hard-coded paths to that separate checkout and is excluded from package builds; do not regenerate it as a routine test update. `test-correctness.R` checks the corrected Hessian-bread draw mapping rather than comparing those rows to the old reference.
- The model requirements include a vector-valued generated quantity `log_lik` (one contribution per pseudo-observation); magnitude refits additionally need the `magnitude_adj` data argument on the **refit model** -- `refit_magnitude_adjust()` checks `model` via `check_model_data_arg()`, not just the supplied `fit`, so a fit/model mismatch is caught. Hessian MLE/MAP breads require `model` + `data` or `opt`/`opt_map`; the Stan model must disable *all* priors for `use_priors = 0` to yield a genuine MLE. `adjust_pseudo_posterior()` records per-method failures in `meta$warnings`, so check that field in tests rather than assuming a returned object means every method succeeded.
- `NAMESPACE` and `man/` are generated by roxygen2 (`devtools::document()` after editing roxygen comments); do not edit generated files by hand. Stan-backed examples and vignette chunks are opt-in with `PP_EXAMPLES_STAN=1` and a CmdStan toolchain.
