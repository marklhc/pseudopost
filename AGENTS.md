# Working in pseudopost

- This is one R package. `R/adjust.R` is the adjustment entry point; `R/requirements.R` validates cmdstanr fits; `R/draws.R` maps target covariance to adjusted draws. The Stan fixtures in `inst/test-models/` back the tests; the detailed model requirements are in `vignettes/pseudo-likelihood-requirements.Rmd`.
- Run tests from the package root with `devtools::test()`; focus on a file with `devtools::test(filter = "combos")` (matches `test-combos.R`). For fast pure-R iteration use `PP_SKIP_STAN=1 Rscript -e 'devtools::test()'`. Full Stan-backed tests need cmdstanr, Rcpp, a working CmdStan installation, and (for the pairwise fixture) lavaan; they compile and sample, so are substantially slower.
- `tests/testthat/helper-fit.R` lazily compiles each Stan fixture once per R session with `force_recompile = TRUE` and caches the live `CmdStanModel`. Do not reuse a precompiled executable/model from another session for tests using `hessian`, `constrain_variables`, or `unconstrain_draws`: cmdstanr model methods fail on that path.
- `tests/testthat/_reference/expectations.csv` is a regression baseline from the external pairwise-cfa implementation. `tools/capture_reference.R` regenerates it using hard-coded paths to that separate checkout and is excluded from package builds; do not regenerate it as a routine test update. `test-correctness.R` checks the corrected Hessian-bread draw mapping rather than comparing those rows to the old reference.
- The model requirements include a vector-valued generated quantity `log_lik` (one contribution per pseudo-observation); magnitude refits additionally need the `magnitude_adj` data argument. Hessian MLE/MAP breads require `model` + `data` or `opt`/`opt_map`; the Stan model must disable *all* priors for `use_priors = 0` to yield a genuine MLE. `adjust_pseudo_posterior()` records per-method failures in `meta$warnings`, so check that field in tests rather than assuming a returned object means every method succeeded.
- `NAMESPACE` and `man/` are generated by roxygen2 (`devtools::document()` after editing roxygen comments); do not edit generated files by hand. Stan-backed examples and vignette chunks are opt-in with `PP_EXAMPLES_STAN=1` and a CmdStan toolchain.
